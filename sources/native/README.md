# P5Cast Direct

This Windows x64 process runs the PS5 Remote Play session using libchiaki 1.10.1 from upstream commit `f30da0aaeb96fc0026cc03683153f682352e7d7c`. The P5Cast player receives H.264 or HEVC access units directly over a local pipe. The core decodes stereo Opus and sends input from the first SDL-compatible game controller. It opens a network session only after the player accepts the pipe and the dashboard supplies a registered host.

## Building and checking

Run `powershell -NoProfile -ExecutionPolicy Bypass -File sources/native/Build.ps1 -Verify` in the repository on Windows x64 with Git for Windows installed. The build uses a hash-pinned private MSYS2 toolchain under the current user's local application data. Verification uses SDL's dummy and disk audio backends, a virtual controller, and local named pipes. Audio fixtures exercise packet bursts, starvation, gain changes and stereo PCM output. The resulting `bin` directory includes the native executable, its runtime DLLs, notices and source archive. [Official chiaki-ng release](https://github.com/chiaki-ng/chiaki-ng/releases/tag/v1.10.1) · [MSYS2 packages and source recipes](https://packages.msys2.org/)

## Player protocol

The dashboard passes `P5CAST_DUALSENSE_FEEDBACK=1` or `0` when starting a stream. With feedback enabled, the helper requests DualSense support when the selected controller is a DualSense or DualSense Edge, or when no controller has attached yet. A generic controller present at startup uses the legacy session profile. The polling thread sends the console’s L2/R2 effects and strength to SDL and releases the triggers on disconnect. A separate worker matches the controller HID path to its four-channel Windows render endpoint by device container ID. It resamples the console’s stereo haptic PCM onto the rear channels. The game audio decoder and its volume control use their own stream.

`CadrivectDirect.exe pipeName host codec [fps [videoKbps [height]]]` accepts a random local pipe name, a reachable console address, codec 1 (H.264), 2 (HEVC) or 3 (HDR HEVC), and 30 or 60 frames per second. The defaults are 60 FPS and 1080p. The optional height selects a console stream profile. With a zero or omitted bitrate, the 1080, 720, 540 and 360 profiles request 15,000, 10,000, 6,000 and 2,000 kbps respectively. A value from 2,000 to 100,000 kbps overrides the requested bandwidth in the console handshake. This matches the range in chiaki-ng's PS5 settings. The console controls its actual output bitrate. [Upstream PS5 bitrate controls](https://github.com/chiaki-ng/chiaki-ng/blob/f30da0aaeb96fc0026cc03683153f682352e7d7c/gui/src/qml/SettingsDialog.qml#L1401-L1418) · [Console launch specification](https://github.com/chiaki-ng/chiaki-ng/blob/f30da0aaeb96fc0026cc03683153f682352e7d7c/lib/src/launchspec.c#L20-L25)

The dashboard writes a 16-byte registration key and 16-byte session key to the helper's inherited standard input. Four optional ASCII login PIN digits may follow. The caller closes stdin after writing.

For dashboard sessions the additional `--rest-control` flag enables the explicit PS5 rest command. The dashboard creates current-user events scoped to the helper PID and session pipe. The helper calls `chiaki_session_goto_bed` once when requested during a connected session and signals acceptance or rejection. Acceptance means libchiaki queued the command locally. A separate disconnect event wakes the session loop and any blocked video write so the helper can release controller feedback before exiting. Normal disconnects and helper exits send no rest command.

When the dashboard redirects the helper's stdout during a managed session, a connected helper writes the selected numeric console address there once. An opted-in game-title lookup sends one read-only discovery request to UDP port 9302 on that exact address. A matching ready PS5 response can supply `running-app-name`. The query times out after 1.2 seconds if the console omits a reply. No credentials are involved. [Upstream PS5 discovery](https://github.com/chiaki-ng/chiaki-ng/blob/f30da0aaeb96fc0026cc03683153f682352e7d7c/lib/src/discovery.c)

The player creates a local input-only byte pipe before starting the core. The dashboard requests `CDV3` through the helper process environment (`P5CAST_DIRECT_STATS_VERSION=3`). With no negotiation the core sends `CDV1` when `videoKbps` is omitted or `CDV2` when it is supplied, followed by a little-endian 32-bit codec ID. Each video packet contains a 32-bit byte count followed by one Annex-B access unit, up to 16 MiB. A new profile begins with parameter sets attached to its first random-access picture.

A zero count introduces a telemetry record. CDV1 sends four little-endian unsigned 32-bit values in order. They hold queued PCM in microseconds, playback callback underruns, startup network RTT in microseconds and target audio queue duration in microseconds. CDV2 appends compressed Opus bits per second, negotiated sample rate in Hz and negotiated channel count. CDV3 appends four session totals for video frames that libchiaki reported lost on picture delivery, audio concealment requests from the receiver (missing audio units), local PCM queue trims after input bursts, and compressed video handoffs to the player taking at least 15 ms including writer lock and pipe writes. Two more CDV3 words report the maximum measured gaps between decoded PCM block arrivals at the queue and between SDL output callback starts, respectively, in microseconds since the last sample. An interval needs two timestamps to produce a gap. If the writer is busy with a picture, peaks and compressed bytes carry over into the next published interval. Both measurements include local scheduling. A slow handoff occupies the shared audio/video receive worker and can delay audio delivery. These counts distinguish receiver loss from local queue behavior. They do not measure Wi-Fi signal, UDP packet loss percentage or physical link loss. `UINT32_MAX` represents an unavailable measurement. Incoming audio bitrate counts the actual compressed bytes delivered to the Opus decoder over elapsed time, excluding packet headers, redundant recovery and generated loss concealment. Audio output follows the stream's mono or stereo format. The receiver validates Opus output rates and accepts decoded packets up to 120 ms long. The library exposes no setting to request a specific console audio bitrate. The PCM queue starts at 15 ms. An underrun counts once when active playback needs more samples than the queue holds. Repeated underruns within three seconds raise the rebuffer target by 10 ms, up to 55 ms. After each ten seconds of uninterrupted playback without a trim, the target falls by 5 ms, down to 15 ms. A short blend releases surplus frames gradually. The reported target tracks these changes. A burst beyond target plus 45 ms trims to target plus 15 ms where the incoming block size permits. Underrun recovery and volume changes use 2 ms ramps. Queue timing excludes the Windows mixer and playback device buffers. The core ends its session when the player disconnects.

`CadrivectDirect.exe --register host` takes an eight-byte PSN account ID followed by the eight ASCII digits from the console's Link Device screen via inherited stdin. On success its inherited stdout yields 74 bytes: `CDR1`, six hardware-address bytes, a 32-byte zero-padded UTF-8 nickname, a 16-byte registration key and a 16-byte session key. The dashboard protects the result with Windows DPAPI. Stdout and stdin must both be redirected pipes. The core never writes keys or PINs to a file.

The dashboard launches the helper with `--session-control`. A current-user mapping alongside its other session controls holds a single aligned 32-bit volume percentage. The dashboard writes the saved level before passing the credentials. The helper opens the mapping read-only before starting a session and scales decoded signed 16-bit PCM before adding it to the playback queue. A missing required mapping exits with 28. Standalone CLI calls and the earlier `--rest-control` switch retain their original full-volume behavior.

Exit codes 20 through 27 indicate invalid input, unavailable player pipe, initialization failure, PS5 session failure, required console login PIN, incorrect console login PIN, audio-device failure, and registration failure respectively.

Codes 28 and 29 indicate unavailable session volume control and unsupported audio format. The Direct helper preserves specific session results from libchiaki: 30 for Remote Play in use, 31 for a refused TCP connection, 32 for a remote stream disconnect, 33 for an incompatible Remote Play version, 34 for a console Remote Play service crash, and 35 for an explicit registration failure. A stopped session or remote console shutdown exits with 0. Unclassified errors keep code 23.

## Source and licenses

The native core is distributed under the upstream Affero GPL v3 with its OpenSSL exception. Its full license, statically linked third-party notices, runtime package versions and available shared-library notices accompany the executable. The source archive includes the core and the libchiaki, nanopb, jerasure and gf-complete sources used in this build. To compile from the extracted archive with the MSYS2 UCRT64 dependencies listed in `packages.sha256`, run `cmake -S . -B out -G Ninja -DCMAKE_BUILD_TYPE=Release -DCMAKE_POLICY_VERSION_MINIMUM=3.10 -DCHIAKI_SOURCE="$PWD/upstream"` followed by `cmake --build out --target CadrivectDirect`.
